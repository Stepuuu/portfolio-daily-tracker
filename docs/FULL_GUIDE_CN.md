## 开始之前

- 持仓和现金**只来自账本**：记一笔、导入券商文件，或确认助手提出的方案；确认前都会先预览变化。
  不再手动编辑持仓 JSON 或 `config.json`。
- 它不连接券商、不下单，也不提供投资建议。提醒只是通知，不是券商的止损单。
- 行情来自公开接口（先东方财富，再腾讯，最后雅虎；前一个取不到的价格才问下一个），可能延迟或中断。每个价格都标着来源和时间，成交价以券商的成交回报为准。
  东方财富和腾讯默认直连，不走环境里的代理（境内服务器上东方财富的接口可能连不上，腾讯通常直连可用）；需要代理时设置 `TRACKER_EASTMONEY_PROXY=1` 或 `TRACKER_TENCENT_PROXY=1`。`TRACKER_QUOTE_SOURCE=tencent` 只用腾讯行情。
- 价格提醒和每日例行任务只在后端运行时工作，关掉后端就不会提醒。

## 安装与启动

需要 Python 3.10+、Node.js 22.12+，本地启动脚本需要 Bash 4.3+；或使用 Docker（含 Compose）。

### 本机运行

```bash
git clone https://github.com/Stepuuu/portfolio-daily-tracker.git
cd portfolio-daily-tracker
python3 -m venv .venv
source .venv/bin/activate
make setup
make start
```

`make setup` 会：安装 `dashboard/requirements.txt` 中的 Python 依赖，在 `dashboard/frontend` 运行 `npm ci`，
在文件不存在时复制两份配置模板（`dashboard/config.json` 和 `engine/portfolio/config.json`），创建数据目录。

`make start` 启动后端（`127.0.0.1:8000`）和网页（`127.0.0.1:3000`）。只启动后端用 `make backend`，停止用 `make stop`。
打开 http://localhost:3000。

### Docker

```bash
docker compose up -d
```

网页在 http://localhost:3000，后端端口 8000 只绑定在本机。数据目录 `engine/portfolio` 挂载到容器的 `/app/portfolio`，
模型设置保存在名为 `dashboard-data` 的卷里。`make docker` 等于 `docker compose up --build`（前台运行）。

Docker 下有两点不同：后端镜像只包含 `dashboard/`，所以[收盘后自动快照](#收盘后自动快照)显示「不可用」；
环境变量要写进 `docker-compose.yml` 里 `backend` 服务的 `environment`（默认只传入 `TRACKER_ALLOWED_HOSTS` 和两个 API Key）。

### 演示模式和研究模式

- `make demo`：第一次运行时在 `.demo/portfolio` 生成虚构数据（旧版本留下的演示目录会重新生成，但只在目录里全是演示数据生成程序写入的内容时；里面有任何其他记录、账户、工作台数据或文件时不做任何改动，提示后退出（退出码 2）；用未发布的开发版本生成过的演示目录也会这样被拒绝，删掉 `.demo/portfolio` 后重新运行即可），然后以只读的演示模式启动。页面顶部显示
  「演示模式 · 数据为虚构，只读」，所有写入按钮都不可用并说明原因。适合先看一遍所有页面。
- `make lab`：只启动 研究 和 设置，不需要账户。

### 用其他地址打开

后端只接受 `localhost`、`127.0.0.1`、`[::1]` 和 Compose 服务名 `backend` 这几个主机名。用局域网地址或反向代理域名打开时，
把名字写进 `TRACKER_ALLOWED_HOSTS`（逗号分隔）并重启后端。注意：这不是登录验证，见 [安全说明](SECURITY.md)。

## 设置向导

地址 `/setup`。全新安装时今日页会自动带你去一次；之后可在 设置 › 关于与帮助 › **重新运行设置向导** 打开，
已经保存的内容不会丢失。每一步都显示真实状态（已完成 / 待处理 / 可选），都可以跳过。

1. **欢迎**：选择建立期初的方式：
   - **从零开始**：新建账户，填写现金、持仓和累计净投入；
   - **导入券商文件**：用券商导出的持仓或交割单建立账本（打开导入页，见[导入券商文件](#导入券商文件)）；
   - **迁移旧版持仓**：把 v3.2 的持仓文件转成期初余额，核对后入账；
   - **先看演示**：用虚构数据浏览全部页面，什么都不会保存。
2. **账户与期初**：账户名、各币种现金、**累计净投入**（你一共投进这个账户的本金，人民币，必填）、基金合计和每只持仓的数量与成本。
   金额都是人民币时，页面会给出一个建议值，写着「按现金＋持仓成本＋基金估值估算，只是参考：请改成实际累计转入的本金」，
   只在你点用时才填入。注意：入账后这个数字不再标为估算，今日页的总盈亏按它计算，所以请尽量填实际转入的本金。
   点 **预览入账**，核对后 **确认入账**。
3. **费率**：每个账户的佣金率和最低佣金（A 股预设万 2.5、最低 5 元，可打开「免五」），港股、美股需要自己填完整的
   费率模型才会估算。
4. **行情与提醒**：检查能否取到行情、提醒监控和每日例行任务是否在运行、通知渠道。
5. **AI 助手**（可选）：选择 DeepSeek、OpenAI、Anthropic 或兼容接口，填写模型和 **API 密钥**，保存后点 **测试连接**
   （只测试已保存的设置）。密钥只写不读：页面和接口都不会返回它。
   - 保存的密钥只属于保存时的地址（协议、主机、端口）和服务商：改成别的地址或服务商再保存，原来的密钥会被清除，
     远程地址需要重新填写密钥。
   - 服务器环境里设置了 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` 时，保存到对应的官方地址（选这一家，或在兼容接口里填官方地址）
     可以不填密钥；本机地址（如 Ollama）也不用填。页面只在接口会拒绝保存的地方要求填写密钥。
   - 页面会原样显示已保存的 **API 地址**（包括路径，不含查询参数），所以不要把密钥写进地址，填在「API 密钥」一栏。
6. **完成**。

### 迁移旧版持仓

向导会查找两类 v3.2 文件，只读不改：

- 数据目录下 `holdings/<日期>.json`（引擎的每日持仓）：取期初日期当天或之前最新的一份；
- 后端工作目录下 `data/portfolio.json`（旧「持仓」页的数据）：迁移成一个账户（默认名 主账户），没有累计净投入，需要你填。

文件里的数字按原样的十进制读取。读不出来的值（数量、成本、代码、自相矛盾的现金）会逐项列出让你补填，或者把那一行留在外面；
没有日期的文件会写明要你填哪一天。旧文件没有记录累计净投入的账户，要先填写才能预览，不会按 0 入账。
生成的是一份普通的账本方案，核对后确认；文件内容在核对期间被改动的话，这份方案会作废，需要重新生成。
已经迁移了一个账户之后，其他还没进账本的旧文件和账户仍会列在 **迁移旧版持仓** 里；只列出还有内容没迁移的来源。
已经全部迁移的文件不会再出现，`data/portfolio.json` 迁移过一次后，换一个账户名再迁移也会被拒绝，同一份资产不会记两次；
那次迁移已经冲销时除外，可以再迁移一次。

## 今日

地址 `/`。顶部一行是市场状态（如「A股 未开盘」「美股 已收盘」）、行情来源和 **今日快照** 的状态。

- **总资产**：所有账户的持仓市值、各币种现金和基金合计，按当前汇率折算成人民币。
- **今日盈亏**：按持仓股数计算的价格变动和当天交易的费用；今天买入的部分从成交价算起，卖出的部分算到成交价为止。
  不含分红、单独记录的费用、汇率变动和基金估值变动。
- **持仓盈亏**：未平仓持仓相对加权平均成本的盈亏（未实现）。
- **总盈亏**：总资产减 **累计净投入**。
- **持仓表**：每行显示名称、代码、行情来源和时间、状态标签，以及现价、涨跌幅、今日盈亏、持仓、成本、市值、
  持仓盈亏、收益率和占比（占整个组合，含现金和基金）。行内的「计划」「提醒 n」标签可以点开；手机上每行有 买 / 卖 / 回测。
- **今日提醒**、**今日事项**（到了复查日的计划）和 **待确认账本方案**。
- **刷新** 会跳过行情缓存立即重新取价。
- 数量和成本按账本里的原始数字显示，不截位；超过 8 位小数时显示为 `≈` 加 8 位小数（如 `≈¥51.47083333`），
  鼠标悬停可看完整值。总资产只是估算时，各行的占比也标为估算。
- 美股在纽约收盘后 30 分钟内（纽约时间 16:30 前，提前收市日 13:30 前）交易所的官方收盘价还没发布，价格显示为「收盘价」
  但标为估算，悬停说明「收盘价尚未最终确定」；满 30 分钟后再次读到的价格才算核实的收盘价。
- 成交稀少、当天收盘后数据源没有再刷新时间戳的持仓，晚上会一直显示「已过期」（估算），直到下一次有带时间的报价。
  午盘同理：午间休市前 20 分钟以上的报价，在午休期间显示为已过期。已知限制：数据源停在休市前 20 分钟以内的一笔成交（如 11:16）时，
  午休期间按它显示为「收盘价 11:16」，算作核实的价格，也不再问备用数据源；下午开盘后恢复正常。

状态标签的含义见[页面上的提示是什么意思](#页面上的提示是什么意思)。

## 行情：自选、搜索与详情

### 搜索代码或名称

任何页面按 `Ctrl K` / `⌘K` 或 `/`，或点页头的搜索框。可以输入代码（`600519`、`00700`、`AAPL`）或名称（`茅台`）。
结果按「持仓 → 自选 → 记住的选择 → 名称列表」排列：

- 6 位数字按前缀判断交易所，`000001` 是平安银行 `SHE:000001`；指数只用 `IDX:` 前缀（如 `IDX:000001` 上证指数）；
- 5 位及以下数字是港股；字母是美股，同一代码在纳斯达克和纽交所都有时会让你选一次并记住；
- 北交所、B 股、申购代码和逆回购代码会列出但不能选，并说明原因；
- 名称列表（A 股和 ETF）在后台下载，暂时没有时仍可按代码搜索，页面会说「名称索引暂不可用」。

### 自选

地址 `/market`。**添加自选** 后，表格显示现价、涨跌幅、涨跌额、备注和提醒数，可以上移、下移调整顺序、写备注；最多 200 只。
页面上方是主要指数。

### 详情抽屉

在今日、自选或提醒里点一只标的，右侧打开详情：日线图（数据源和复权方式写在图下；收盘前的最后一根是临时的）、
你的持仓、提醒规则和交易计划，以及 **设提醒**、**加入自选** / **移出自选**、**去回测**。
详情、自选、指数条和提醒规则里的价格、涨跌和收盘价都保留数据源给出的全部位数（如 $0.8437 不会显示成 $0.84）。

## 价格提醒

地址 `/alerts`（行情 › 提醒）。提醒只通知，不会下单。

### 新建一条提醒

1. 点 **新建提醒**，或在今日、详情抽屉里点 **设提醒**。
2. 选标的和类型：
   - **止损**：现价 ≤ 设定价时提醒；
   - **目标价**：现价 ≥ 设定价时提醒；
   - **涨跌幅**：填带符号的百分比，`-5` 表示跌 5% 或更多，`5` 表示涨 5% 或更多；一条规则只看一个方向；
   - **仓位上限**：这只持仓占整个组合（人民币，含现金和基金）的比例达到设定值时提醒，可限定某个账户。
3. 保存。现价已经满足条件时，页面会提示「保存后下一次检查就会提醒」。没有数据源能报价的代码
   （如落在指数代码段里的股票代码 `SHA:000001`）不能新建提醒，会写明原因。

来自交易计划的规则在提醒页只读（来源显示「计划 #n」），要在计划里修改。

规则表的「现价 / 距离」一栏写「差 …」或「已达到」。「已达到」按监控用的同一个精确比较判断，不是四舍五入后的距离；
距离小到四舍五入会变成 0 时保留两位有效数字。条件已满足、但监控这时跳过了这条规则（如暂停检查、演示模式）时写
「已达到 · 未检查」：这时不会提醒。
已知限制：同一只股票分在几个账户、合计仓位恰好等于上限（精确到小数点后二十位左右）时，新建规则时的「当前仓位已达到上限」提示
可能和监控的判断不一致；仓位高于或低于上限时不受影响。
「今日触发」刷新失败时，次数显示「不可用」并写明原因，不会把旧的次数当成最新的。

### 什么时候检查、怎样提醒

- 提醒监控在后端里运行，只在市场**连续竞价时段**检查，默认每 5 秒一次；夜间、周末、节假日、午休和集合竞价不检查，
  规则显示「休市，不检查」。
- 只用可信的行情：**已过期**、**时间未知**、**不可用** 的价格不用；价格类规则在当天还没成交（昨收价）时不用。
  这时规则显示琥珀色 **暂停检查**，并写明原因和从几点开始。仓位上限规则在组合里任何一个价格或汇率只是估算时也会暂停。
- 触发一次后，价格回到阈值 0.5% 以外（百分比规则为 0.5 个百分点）或到下一个交易日才会再提醒；
  每条规则每天最多 3 次，两次之间至少隔冷却时间（默认 300 秒）。
- 提醒进入页头铃铛（站内通知）。10 分钟内最多 20 条，其中 5 条留给止损；超出的合并成一条汇总。
- 连续三次取不到行情时发一条「行情中断，提醒暂停」，恢复后发「提醒已恢复」。

### 监控状态

提醒页顶部的「监控」一行：**运行中**、**运行中 · 等待开盘**、**运行中 · 没有启用的规则**、**运行中 · 部分规则无法检查**、
**行情不稳定**、**行情中断，已暂停**、**检查出错**、**待命 · 另一个后端进程在检查**（同一数据目录上开了第二个后端，只有一个在检查）、
**未运行**、**已停止**、**没有响应**、**已关闭**（`TRACKER_ALERTS_ENABLED=0`）、**演示模式不检查提醒**（演示模式下每条规则也这样显示）。

详细规则、环境变量和 Docker 下的运行方式见 [ALERTS_AND_ROUTINES.md](ALERTS_AND_ROUTINES.md)。

## 账本：记一笔、流水、持仓与成本

### 记一笔

按 `N`，或点页头 / 手机底部的 **记一笔**。在今日的持仓行、详情抽屉或计划里打开时，会预填标的和买卖方向。

1. **类型**：买入、卖出、分红、入金、出金、换汇、转账、拆股/送转、基金申购 / 赎回 / 估值、费用、利息、冲销，
   新账户用 **期初余额**。
2. **账户** 和 **日期**（成交所在交易所的当地日期；美股成交按纽约日期记）。
3. **标的**：输入代码或名称，从列表里选；也可以直接输入带交易所前缀的完整代码，如 `SHA:600519`、`HKG:00700`、`NASDAQ:AAPL`。
   卖出时只列出这个账户在该日期持有的标的，并显示「可卖」和 **全部**。同一只证券的不同写法（如 `HKG:700` 和 `HKG:00700`，
   美股类别股用点或横线）：账户在成交日期已经持有这只证券时，新记的交易记入账户那天持有的那种写法（两种写法都持有时：你输入的正是其中一种就用它，否则用持仓较大的那种）；
   那天没有持有时按你输入的写法记；只有补记更早的交易（日期早于该账户这只证券的其他记录）、而这些记录只用过一种写法时，沿用那种写法。升级前已用两种写法记入同一标的的旧账本保持原样，仍显示为两行、分别计算。
4. **数量** 和 **价格**：价格旁边显示现价和昨收，可点 **按现价** 填入（「成交价以成交回报为准」）。A 股按 100 股一手提示。
   注意「昨收」没有自己的时间，旁边显示的是当前报价的时间。
5. **费用**：按账户费率自动估算并显示明细，标为 **估算**（「按费率计算，不是成交单上的费用」）。可以改成成交单上的数字；
   留空则按估算入账，备注里记上「费用为估算」。这个标记只在这笔流水的备注里：用它算出的成本和盈亏不再标估算。
   券商实际收费不同时，在流水里冲销这一笔，再按实际费用重记，或导入券商文件。港股、美股没有设置费率时不会估算，需要自己填。
6. 换汇和外币入金会显示参考汇率（「参考汇率不是银行实际成交汇率」），点 **按参考汇率** 才会填入；最好填银行实际到账金额。
7. 点 **预览入账**（或回车）进入 **核对入账**：现金、股数、成本的前后变化，与交易计划的对照（如「高于计划入场区间」），
   以及提示（如现金不足）。点 **确认入账** 才写入账本；**返回修改** 回到表单；**放弃** 丢弃这份预览。
8. 确认后可点 **再记一笔**，账户和日期保持不变。

手动预览 2 小时内不确认会过期；账本在预览之后有了变化时，页面显示「预览已过期」，需要重新预览。
B 股（`SHA:900xxx`、`SHE:200xxx`、`SHE:201xxx`）以美元或港币交易，账本按人民币记录沪深标的，所以不能记入；
升级前生成的 B 股方案确认时也会被拒绝。港股通成交不能用记一笔记录，请导入券商文件。
期初余额必须填累计净投入；只有不经页面、直接调用入账接口时，不带它才会按 0 记账。

### 流水

地址 `/ledger`。按日期列出所有已确认的记录；要更正一笔，用 **冲销** 生成一份冲销预览并确认，原记录保留。
页面右上角的 **导入** 进入导入页。

记账规则见 [LEDGER.md](LEDGER.md) 和 [ACCOUNTING.md](ACCOUNTING.md)。

## 导入券商文件

地址 `/ledger/import`（账本 › 导入）。规则和字段的完整说明见 [IMPORT.md](IMPORT.md)。

### 能读什么

- 交割单、资金对账单、持仓，以及本系统的 CSV 模板（在上传页点 **下载模板**）；
- CSV、TXT、XLS、XLSX、另存为 `.xls` 的网页；UTF-8、GBK；不超过 5 MB、2 万行；
- 同花顺、东方财富、通达信等格式有预设，但**预设没有用各家券商的真实文件逐一验证**，页面会写「预设未经你的券商文件验证」。
  认错列时在第 2 步改正，改过的列对应会按「账户 + 表头格式」保存，下次自动使用。

### 四个步骤

1. **选择文件**：选导入到哪个账户（或填新账户名称），选择或拖入文件。
2. **核对列**：检查每一列对应什么（日期、代码、业务、数量、价格、金额、费用列……）。
   - 有「列冲突」（例如两列成交价格且数值不同）时必须选定一列；
   - 文件里有多个资金账号或股东代码时，要选哪些属于这个账户；其他的行会成为 **需处理**；
   - 5 位及以下的数字代码要选按港股还是 A 股读。
3. **预览与去重**：每一行的状态和合计，以及 **对账**。状态说明：

   | 状态 | 含义 |
   |---|---|
   | 新 | 可以入账，默认勾选 |
   | 可能重复 | 账本里已有同账户、同日期、同标的、同类型、同数量（或同币种同金额）的记录，例如手工记过，默认不勾选 |
   | 已导入 | 这一行已经入账，不会重复 |
   | 与已入账记录不同 | 同一编号已入账但内容不同，不入账，并列出不同的字段 |
   | 需处理 | 缺少或无法确定入账需要的信息，写明原因；改正前不入账 |
   | 跳过 | 撤单、废单、申购配号、指定交易、转托管、冻结等 |
   | 不支持 | 北交所和 B 股 |
   | 已合并 | 逆回购的借出一行，已并入购回一行 |

4. **确认**：点 **生成入账预览**，核对后 **确认入账**。超过 1,000 条记录时分批确认（如「第 1/3 批」），上一批确认后再准备下一批。
   只有剩下的行全是已导入、跳过或已合并时，页面才写「全部已导入」；否则会说明还剩哪些行。

### 几种行怎样入账

- **港股通**：按人民币清算金额（发生金额）记一笔换汇加港币成交，现金变动和清算金额完全一致；文件里用港币写的费用按结算汇率
  （或清算金额推算出的汇率）换算成人民币，不会当成人民币。
- **分红**：文件写明税前金额、扣除的税费和到账金额，并且「税前 − 扣除 = 到账」时，按到账金额记；对不上时这一行需要处理，
  请填写实际到账的金额。
- **带 `$` 的金额**：成交价、成交金额上的 `$` 按这只证券所在市场的货币读（美股是美元，港股是港币）；没有任何线索判断是美元还是港币时，
  这一行需要处理。
- **同一天的顺序**：没有成交时间时，按这个账户自己的资金余额推出先后（其他资金账号的余额不参与）；连余额也没有时，
  只调整这个账户的买卖：卖出排在要用这笔钱的买入前面，所以不会因为行的顺序被判成现金不足；其他行（入金、分红、基金、
  本系统模板的行等）保持文件里的顺序。当天有拆股/送转或其他改变股数的行、且当天也买卖了同一只证券时，整天保持文件里的顺序。按最新在前排列的导出也能识别。
- **表格里的数字**：XLS / XLSX 中以数字保存的单元格按原值读取，不受文本单元格小数逗号写法的影响。
- **重叠的导出**：两份导出有重叠、又没有成交编号时，已入账的成交先按自己的价格配对，所以只会记入新的那一笔。
  两笔都有成交编号且编号不同时，就是两笔成交，不会标为可能重复；编号比较时不看开头的 0（表格会把文本 `000123` 存成数字 123）。
- **不同写法的代码**：对比是否已导入、对账时按同一只证券比较，不论写法（如账本里记成 `HKG:700`、文件里是 `00700`）。
- **需要手工处理**：新股中签缴款与入账、配股、ETF 申赎、场外基金申购、融资融券、通用的资金调整会标为需处理或跳过，
  请导入后用记一笔补记；北交所不支持。
- **已知限制**：同一只港股在账本里有两种写法时（两个账户分别是 `HKG:700` 和 `HKG:00700`，或同一账户先以 `HKG:00700` 清仓、
  再以 `HKG:700` 买回），导入持有 `HKG:700` 的账户的卖出，
  预览可能提示「卖出 100 股，但账本当时只持有 0 股。请核对数量；如果数量没错，请先在账本里补录期初持仓或更早的买入。」
  文件里的代码会被读成另一种写法，改文件里的代码或在行编辑里改代码都一样。请把这一行设为跳过，
  用记一笔记这笔卖出（记一笔会记入该账户当时持有的写法）。
- **已知限制**：没有成交时间、也没有资金余额的文件里，同一天的买入排在为它付款的入金之前时，这笔买入会提示「现金不足：…」、
  需要处理（入金照常记入）。在处理这一行时勾选「允许融资」（这笔买入带上允许融资的标记，入金之前现金暂为负数），或在文件里把入金行移到买入之前再导入。

### 需处理的行怎么办

1. 点 **处理第 n 行**，对话框会写明「为什么需要处理」以及要改哪些字段。
2. 改正后 **保存修改**；不想导入就 **设为跳过**。
3. 原因是列对应或账户时，回到 **核对列** 处理。
4. 对话框写「这一行无法在这里修改」时，导入后用记一笔补记，或改好文件重新导入。

没处理的行不会入账；对账结果会把它们列为可能的差额原因。

### 对账

- 文件有资金余额、股份余额列时，按「文件最后一天的账本 + 这次导入的行」与文件余额比较：**一致**，或差额和可能的原因。
  有差额时要先勾选「我已核对这些差异，仍要生成入账预览」。会改变这笔现金或股数的行里还有需处理、不支持或没勾选的，
  即使数字对上也写 **未核对**（并写明有几行没算进去），不会写一致。
- 持仓文件导入到**新账户**：生成期初余额。期初日期、各币种现金和累计净投入不在持仓文件里，需要你填写；
  累计净投入会按「现金＋持仓成本＋基金估值」给出建议值，并写明「按现金＋持仓成本＋基金估值估算，只是参考：请改成实际累计转入的本金」。
  入账后它不再标为估算，今日页的总盈亏按它计算。券商的「参考/摊薄成本」含已实现盈亏，可能与账本的加权平均成本不同。
- 持仓文件导入到**已有账户**：列出文件数量与账本数量（一致 / 差额 / 未核对），有差额的行可以点 **记一笔** 补记；不会自动生成更正交易。

### 重复导入和过期

同一个文件再导入一次，全部显示「已导入」，不会重复入账。上传的文件本身不保存；导入记录 30 天后删除。
入账预览和这次导入绑定：导入被修改、删除或过期，或账本有了变化，这份预览就作废，需要重新 **生成入账预览**。
导入规则有变化的版本（规则版本是 `dashboard/core/importers/__init__.py` 里的 `INTERPRETATION_VERSION`，4.0.0 为 4）
升级后，旧规则生成、还没确认的入账预览在确认时会被撤回，请重新导入同一个文件。

## 交易计划

地址 `/plans`（计划与复盘 › 计划）。计划只用于记录和提醒，不会下单。

1. **新建计划**：标的、账户（不选则对所有账户生效）、为什么买、什么情况说明我错了、入场区间、止损、目标、
   计划仓位（占组合的 %）或计划股数、复查日。
2. **保存草稿** 或 **保存并启用**。启用时自动建立止损、目标价和（填了计划仓位时的）仓位上限提醒；
   结束或取消计划时这些提醒停用。同一标的、同一账户只能有一个启用中的计划。
3. 计划列表和详情显示现价、距止损、距目标、当前仓位与计划仓位、按计划算的最大亏损（港股、美股按当前汇率折成人民币，汇率未核实时标为估算）。
   美股收盘价还没最终确定时，计划里的价格和今日页一样显示为琥珀色并写明原因。
   - 启用中的计划在不改入场区间时，可以把止损上移到保本或盈利的位置（止损仍须低于目标；草稿的止损仍须低于入场价）。
     这时最大亏损记为 0，并写明止损锁定的盈利，如「止损价 … 不低于入场价上限 …：触及止损时不亏损，按计划股数 … 锁定盈利 …」。
   - 计划的启用日和结束日按标的所在市场的当地交易日算：美股计划按纽约日期判断某笔成交是否在计划期内。
4. 记一笔和导入的预览里会出现「对照交易计划」：没有计划的买入、价格不在入场区间、在止损价或以下买入、超过计划股数或仓位、
   低于止损卖出、未到目标卖出等。**只提示，不拦截**：账本记录实际发生的事。
5. 结束计划要写结束原因；取消原因可不填。计划详情里能看到关联的成交和提醒规则，并可 **回测这个计划**。

## 今日简报

地址 `/review`（计划与复盘 › 今日简报）。A 股交易日自动生成两份：

- **盘前简报**（08:45）：隔夜美股、港股和 A 股指数；每个持仓和自选离止损、目标还有多远；到复查日的计划和笔记；
  A 股持仓前一收盘以来的公告和新闻（来自第三方网站的原文，仅供查阅）；最近触发的提醒；待确认的方案。
- **盘后简报**（15:45）：当天的成交和计划核对；各持仓的今日盈亏（每行写明用的是哪一天的收盘价或盘中价）；当天触发的提醒；
  越过止损或目标的持仓；待确认的教训。

每个数字都由程序从账本和带标签的行情算出，并注明来源和时间；取不到的写「不可用」和原因，整段数据源不可用时写「数据源不可用」。

- 成交的数量、价格和费用按账本里的原始数字写，不截位。
- 同一个持仓上，提醒规则和交易计划写了同一个止损或目标价时只列一次、只算一次越过，并写出背后的每个计划和规则。
- 「越过止损或目标的持仓」里，有的持仓只有过期的价格，或美股收盘价还没最终确定时，这个数标为估算，并列出没能核对的持仓。
- 「待确认」统计按当前账本版本生成、仍能确认的全部预览（已经过期的手动预览不算）。账本页最多列出 30 条常规方案和
  10 条手动预览，所以条数很多时两边的数字会不一致。
- 简报只进站内通知（铃铛），不推送到飞书；飞书只推送收盘日报。
可以用 ‹ › 切换交易日，点 **生成** / **重新生成** 手动生成。简报生成失败时仍会保存已生成的部分，并显示何时重试。
设置 `TRACKER_BRIEF_COMMENTARY=1` 后会附上对话模型的点评，单独显示为「模型点评」，不提供任何事实。

时间和开关：`TRACKER_PREMARKET_TIME`、`TRACKER_POSTMARKET_TIME`、`TRACKER_PREMARKET=0`、`TRACKER_POSTMARKET=0`，写在环境变量或 `.env`，重启后端生效。

## 收盘后自动快照

后端运行时会自己生成收盘快照，不需要每天手动执行命令，也不需要另开调度器：

- **时间**：A 股交易日 15:40（北京时间）。周末和交易所休市日不运行（休市表见 `dashboard/core/market/holidays.json`）。
- **只在后端运行期间**：后端在 15:40 之后启动，会补做**当天**的快照；后端没有运行的日子不会事后补做，请用下面的手动命令。
- **做什么**：运行 `engine/scripts/portfolio_daily_update.py --action auto-pipeline --date <当天>`：持有写入锁，生成快照、
  `history.csv` 当日记录和 Markdown 日报（保存在 `engine/reports`；设置 `TRACKER_REPORTS_DIR` 可改到其他目录，例如数据目录下的
  `reports`，随数据一起备份）；数据目录的 `config.json` 配置了 `feishu_chat_id` 时推送飞书日报，未配置时只保存。
  日期按北京时间计：各脚本不写 `--date` 时是北京时间的今天，快照的生成时间带时区记录，日报末尾的生成时间写成北京时间
  （如「2026-11-20 15:40:12（北京时间）」），与服务器所在时区无关。
  当天快照已存在时不重做，只补齐缺少的历史记录或日报。
- **缺价格时**：任一持仓取不到价格，不保存快照（不会按 0 计算），记为失败。
- **只记收盘价**：还在交易、或收盘价还没确定的市场的价格不是收盘价，不会记入快照。持有港股时，15:40 港股的收盘价还没确定
  （收盘竞价结束、16:10 才确定），这次运行**不算失败**：状态为「等待中」，原因写「等待港股收盘价确定，16:10 后记入」，
  不发通知、不占用重试次数，16:10 之后调度器的第一次检查（约一分钟内）生成快照。等待期间手动运行会立刻检查一次：能确定就生成，
  不能确定就照旧等待（还是同一条记录，不算失败、不发通知）。只持有 A 股时照常 15:40 生成。
  当天的快照只记当天的收盘价（A 股、港股是当天的交易日，美股是前一晚纽约的交易日）：在当天收盘之前生成（例如凌晨在飞书卡片
  记了一笔当天的交易后生成日报），无论走哪条路径（收盘快照、`--action auto-pipeline` 或 `pipeline`、飞书卡片的日报），
  都不会把前一天的收盘价当成当天的记入，而是和收盘价还没确定时一样等待（只持有 A 股时等到当天 15:00）；当天休市的市场照旧沿用
  最近一个交易日的收盘价。旧版本在收盘价确定之前生成的当天快照（按快照里的生成时间判断），收盘价确定之后运行的流水线会按收盘价
  重新生成，连同历史记录、日报和推送，不会只补齐。
  美股持仓在 15:40 用的是前一晚纽约已确定的收盘价，不用等；只有晚上纽约开盘后才运行的重试会等到纽约当天的收盘价确定
  （纽约时间 16:30，提前收市日 13:30）再记入。港股半日市（12:00 收市，12:10 确定）和港股休市日都不用等。
  价格是不是收盘价，按今日页同一张规则表判断（`dashboard/core/market/quotes.py`），向 Yahoo 请求的代码也和今日页相同
  （如 `HKG:00700` → `0700.HK`、`NYSE:BRK.B` → `BRK-B`）。雅虎取不到、或取到的价格不能记入的持仓，再一次性向腾讯行情请求
  （代码也和今日页相同，如 `sh600519`、`hk00700`、`usBRK.B`；直连，`TRACKER_TENCENT_PROXY=1` 时走环境里的代理；
  `config.json` 的 `tencent_url` 可替换地址），按同一张规则表判断，记入时输出「价格取自腾讯行情」。只是在等收盘价确定的持仓
  不问腾讯（哪个数据源都要等）；在等收盘竞价成交到达雅虎的持仓会问腾讯，腾讯已有能核实的收盘价就直接记入。
  快照的每个持仓用 `price_source`（`yahoo` 或 `tencent`）记录价格取自哪里，日报末尾的「数据来源」列出当天实际用到的来源
  （全部来自雅虎时仍是「Yahoo Finance」，部分来自腾讯时是「Yahoo Finance、腾讯」）。
  腾讯的价格只有是**收盘行**才记入：行情时间在该交易日当天、且不早于收盘成交时间（A 股 15:00，港股 16:08，美股 16:00），
  美股还必须在收盘后一分钟内（腾讯不区分盘后成交）；更早的时间（盘中、收盘竞价之前、开盘前的占位）无论何时运行都不记入；
  前一交易日的收盘价只有腾讯标记停牌时才沿用；等雅虎收盘竞价成交时，只有腾讯能核实的收盘价才结束等待，估算不算。
  快照被流水线限制在 120 秒内：腾讯请求最多 6 秒，剩余时间不够留给汇率请求（30 秒）时不再问腾讯，照旧完成或等待重试。
  `TRACKER_QUOTE_SOURCE=tencent` 时只用腾讯，`yahoo` 时只用雅虎，`eastmoney` 时也只用雅虎（快照不读东方财富的行情）。今日页会标为「过时」的价格不当作收盘价：例如 16:10 时数据源还停在
  15:55 的港股价格（早于收盘竞价成交），同样显示「等待中」，原因写「等待港股收盘价确定，最晚 16:28 记入」：收盘竞价的成交价
  随时可能到达数据源（雅虎通常晚约 15 分钟，16:08 的成交 16:23 左右才有），所以每到整 5 分钟（16:15、16:20、16:25）再取一次，
  取到能核实的收盘价就立即记入，不标估算。到了成交时间加数据源的正常延迟（港股 16:28，A 股 15:20）
  仍没有更晚的成交时间（收盘竞价没有成交的冷门股，或数据源不更新收盘时间），就按当天最后成交价记入并标「含估算」
  （见下面的估算标记），这次运行照常完成，不算失败、不发通知。纽约收盘前一分钟以上的最后一笔成交（例如停在 14:42 的价格）
  同样不是收盘价，按当天最后成交价记入并标「含估算」。完全取不到价格时仍按缺价格处理，自动重试。
  金额按账本里的原始数字计算（数量和成本价不截位），和今日页相同。
- **估算标记**：下面几种情况照常生成快照，但标为「含估算」并写明原因，和今日页标「估算」的规则相同：
  持仓在它所在市场最近一个交易日没有新的成交价（可能停牌或数据源未更新），按最近的收盘价记入；当天有成交、但收盘竞价后没有
  新的成交时间，按当天最后成交价记入（原因写「收盘竞价后没有新的成交时间，按当日最后成交价记入」）；收盘价所在年份不在休市表内，
  无法核实；汇率超过 1 小时没有更新，或数据源没有给出汇率时间（汇率和今日页取自同一个来源：先雅虎，雅虎的汇率过期或没有时间时
  用东方财富的离岸汇率，`TRACKER_QUOTE_SOURCE` 只选了其中一个时只用它；腾讯没有可用的汇率，选 `tencent` 时汇率仍先雅虎、再东方财富；
  两个都没有核实过的汇率时，才用其中最新的一个并标估算）；持仓取自旧版持仓文件、还没有[迁移到账本](#迁移旧版持仓)
  （原因写「持仓来自旧版持仓文件，尚未迁移到账本」；这时今日页显示「还没有已确认的持仓」、没有合计，快照却仍按旧文件生成；在 `/setup` 迁移并入账后，之后的快照按账本生成，
  不再带这条标记）。
  标记写在快照文件里（`summary.estimated`、`summary.estimated_reasons`，持仓上是 `estimated_reason`；
  `holdings_source` 记录持仓来自账本 `ledger` 还是旧版文件 `legacy_files`），并显示在：日报开头一行；这次运行的摘要（「含估算：原因」，
  盘后简报的「收盘快照」一行显示的就是它）；组合走势页（走势曲线上的空心点、每日收益记录日期旁的「含估算」、
  该日快照顶部的说明）。走势、回撤和月收益照常使用这些日子的数字；用于复盘前请先核对。
  已知限制：停牌和数据源没有更新无法区分，两种情况都按最近收盘价记入并标「含估算」；停牌股复牌、
  汇率或数据源恢复、持仓迁移到账本之后，带标记的那天**不会自动重做**：当天快照已经存在时，自动快照只补齐缺少的历史记录或日报。
- **第一个快照**：没有更早的快照或历史记录可比时，当天的日变动、出入金和日收益率记为「不可用」（`history.csv` 里留空，
  页面显示 —），不记为 0。
- **失败与重试**：15 分钟后和再 30 分钟后各自动重试一次（最晚到次日 09:00）；仍失败则发一条通知，问题解决后可在
  设置 › 自动化与通知 点 **立即运行**（或 `POST /api/routines/close_snapshot/run`）。
- **查看状态**：今日页顶部的「今日快照」标签（已完成 / 生成中 / 16:10 后记入 / 待重试 / 失败 / 已跳过 / 不可用 / 不会自动生成），
  以及 `GET /api/routines/status`、`GET /api/routines/runs`。等待收盘竞价成交价时，标签写的是下一次查看的时间
  （如「今日快照 16:15 后记入」），最晚记入时间（16:28）只在悬停提示里（「等待港股收盘价确定，最晚 16:28 记入」）。
- **不运行的情况**：演示模式；研究模式 `TRACKER_LAB_ONLY=1`；模拟行情 `TRACKER_QUOTE_SOURCE=fake`；设置 `TRACKER_CLOSE_SNAPSHOT=0` 关闭；
  还没有账本也没有持仓文件时记为「已跳过」。
- **不可用的情况**：数据目录里没有 `config.json`（`make setup` 会从 `engine/portfolio/config.example.json` 复制一份）；
  这一天没有生效的持仓；或者安装里没有快照引擎。
- **Docker**：后端镜像只包含 `dashboard/`，没有快照引擎，状态显示「此安装不含快照引擎（engine/scripts），例如 Docker 后端镜像」。
  请在宿主机用下面的手动命令（可放进 cron，在 15:40 之后运行），它使用容器挂载的同一个 `engine/portfolio` 目录。
- **已有 cron 或独立调度器**：同时使用不会重复生成当天快照，日报由先运行的一方生成和推送。只想保留原来的定时任务时，设置 `TRACKER_CLOSE_SNAPSHOT=0`。

不常驻运行后端时，手动执行同样的流程：

```bash
cd engine && python3 scripts/portfolio_daily_update.py --action auto-pipeline
```

`engine/scripts/portfolio_scheduler.py` 仍可单独运行（北京时间 18:00 询问持仓变化、19:00 运行流水线，与服务器所在时区无关），
它和 `portfolio-cron.sh`、`portfolio-daily.sh` 默认用启动它们的 Python 解释器（shell 脚本为 `python3`，可用 `PYTHON` 指定）；
要在 conda 环境里运行，设置 `CONDA_ENV=<环境名>`（`CONDA_EXE` 指定 conda 可执行文件）。

## 组合走势与笔记

- **组合走势**（`/tracker`）：按每日收盘快照画出的总资产、收益和回撤历史。它读的是快照文件，不是实时估值；
  某一天没有快照时，那一天就没有数据。快照含估算的日子标为「含估算」（见[收盘后自动快照](#收盘后自动快照)的估算标记）。
- **笔记**（`/notes`）：研究笔记，记录投资理由、失效条件和下次复查日；新记录不覆盖旧结论。到了复查日会出现在盘前简报里。

## 回测

地址 `/backtest`（研究 › 回测）。用历史行情检验一个简单规则在一只股票上的表现，并说明这个结果有多可靠。

1. **快速回测**：选标的（输入代码或名称，点开列表可选持仓），或在今日和持仓与成本的持仓行点 **回测**（回测这只持仓）、在详情抽屉点 **去回测**、在交易计划里点 **回测这个计划**。
2. 选方法：
   - **一直持有（对照）**：第一个可交易日买入，一直拿到最后；
   - **均线趋势**：收盘价站上 N 日均线买入，跌破卖出；
   - **超跌反弹**：RSI(14) 低于 30 买入；高于 70、持有满 20 日或亏 8% 卖出；
   - **突破**：收盘价创 N 日新高买入，跌破 M 日最低收盘价卖出；
   - **止损止盈（持仓）**：在指定日期买入，亏 8% 止损、赚 20% 止盈、或从高点回落 10% 离场，三项都可以关掉。
3. 选时间段（近 1 年、近 3 年、近 5 年或自定义）和本金，开始回测。
4. 结果：一段由程序生成的结论、与「同一只股票一直持有」和大盘指数（沪深300、恒生指数或标普500）的对比、收益曲线、回撤、
   每笔交易、月度收益，以及提醒事项（如样本内、未复权、数据拼接、费用假设）。对比算不出来时显示不可用，不显示 0%。
   AI 解读默认不生成，需要时点 **生成 AI 解读**。
   数据结束时还没卖出的持仓不算完整交易，单独列在 **期末仍持有**：买入日、估值日、股数、买入均价、最后收盘价、浮动盈亏，
   状态为「期末估值（未卖出）」；**完整交易** 只列已经卖出的。
5. **历史** 保存每次运行（含运行清单：设置、数据哈希、引擎和费率表版本），可以 **重跑核对**，并显示数据、策略、设置或引擎是否变化
   （上传的策略，指纹也包括它导入的本地模块）。历史一次列 100 条，点 **加载更多** 看更早的；以不复权保存的回测重新打开时仍是不复权。
   v3.2.1 及更早保存的记录标为「旧版本记录」：只显示当时保存的内容，缺少的部分显示不可用，可以导出，但不能重跑。
   **数据** 管理本地日线缓存，按复权方式分别显示每只标的的来源、下载时间、日期范围和是否完整；**更新到今天** 会刷新缓存里的每种复权，
   并写明各自更新到哪一天。**策略文件** 查看内置策略（上传 Python 策略默认关闭，需 `TRACKER_ALLOW_CUSTOM_STRATEGIES=1`）。

成交规则：信号出现后的下一根 K 线开盘价成交，滑点 0.05%；A 股 T+1；每手 100 股（科创板 200 股起、之后按 1 股；港股按 100 股假设并注明）；
一字涨跌停不能成交；每根 K 线成交量最多用 10%；止损止盈在 K 线内触发；没成交的买单 1 根 K 线后失效，卖单最多重试 20 根。
税费按日期从 `dashboard/backtesting/broker/fee_schedules.json` 读取（印花税、过户费、港股交易费和征费、美股 SEC 费），
佣金默认值只是假设，可以改。**没有建模**：分钟数据、做空、融资、期权、下单、多股票筛选、港股每手股数表、按持有期的红利税、参数优化。
一直持有这类不读指标的方法不自动预热，也不带「参数是在同一段历史上看出来的」和「完整交易太少」这两条提醒。
缓存里的日线停在最近一个已收盘交易日之前时会重新下载（同一序列每小时最多一次，之间的回测沿用最近一次的检查）；数据源仍然没有那一天时，结果截至已有的最后一根 K 线，
提醒事项里写明行情只到哪一天（`data_ends_early`）。
演示模式只能回测演示持仓里的代码，用程序生成的虚构行情，不和指数比较，结果不保存到历史。

已知限制：

- 对比另一个市场的指数时，回测区间落在休市表没有收录的年份（目前 A 股 2026 年，港股和美股 2026–2027 年），
  指数缺少的交易日无法确认是休市，整段指数对比显示为不可用。
- A 股 ETF 一律按 T+1 模拟：黄金、债券、货币和跨境 ETF（如 518880、511010、513100、159941）实际可以当天买卖，
  回测里当天买入的份额不能当天卖出，期末估值也把当天买入的份额说成 T+1 卖不出。
- 收盘后不久（如 15:45）跑过一次、数据源还没有当天日线时，一小时内再跑同一标的不会重新下载，结果仍截至前一个交易日并带
  `data_ends_early` 提醒；一小时后再跑，或在 **数据** 里点 **更新到今天**，才会再去取。

## 助手

点页头的 **助手** 打开对话面板（手机上在底部导航）。助手是可选的：不配置模型时其他功能都能用。

- 配置：设置向导的 AI 助手一步，或 设置 › 模型。支持 DeepSeek、OpenAI、Anthropic 和 OpenAI 兼容接口（如本机的 Ollama、vLLM）。
- 能读：今日页的估值（带行情时间和状态）、行情、自选、提醒规则、交易计划、简报、已确认的成交、研究笔记、日线、技术指标、
  个股新闻和公告。市场宽度、板块和财联社电报默认关闭（`TRACKER_AGENT_BREADTH=1`、`TRACKER_AGENT_CLS_FLASH=1` 开启）。
- 只能提出方案：记账、提醒、计划、加自选和教训都是待你确认的预览（它给出的金额和数量按原样的十进制数字读取，带浮点误差的数字会被拒绝），出现在页头的 **待确认** 和对话里，点 **核对方案** 查看。
  它提出期初余额前，必须先从你这里得到每个账户的累计净投入，否则不会生成方案。
  它从对话中归纳的教训和交易画像修改，会成为 设置 › 交易偏好 里待确认的提议；你放弃过的教训不会再被提出，
  你说不喜欢的板块（如「我不喜欢银行股，只喜欢科技股」里的银行）不会被记成偏好。
  已知限制：板块按句式识别，「银行股我不会买入，我只喜欢科技股」可能把两个板块都提为偏好，「我不想追高所以更喜欢银行股」
  可能一个也不提；提议要你确认后才保存，请确认前看一遍。
- 新闻、行情源返回的文字（包括取不到价格的原因）以及你自己保存的名称、笔记，都以不可信数据的形式交给模型；回答里有、但本轮数据里没有的数字会附上脚注。
  脚注只按单位类别核对：回答里的百分比只看是否在本轮数据的某个百分比字段里出现过，不核对它是不是对应的那个指标
  （例如仓位 100% 可以让「涨了 100%」不被加注）；金额、股数同样只按金额、数量这两类核对。请以页面上的数字为准。
  0 元的现价同样按句式识别：「现价 0.00 元」这样的写法会加注，「现价为人民币0.00元」「当前价约为0.00元」这类写法里编造的 0 元可能不加注。
  旧版行情工具的一个数据源没有价格时（开盘前、停牌）会改问下一个数据源；都没有时说不可用，不会当成 0 或 −100%，
  保留第一个给出昨收的数据源的昨收。
- 可以粘贴或拖入截图让它看。识别出的持仓只在对话里展示，**不会入账**；成本价只取图片里明确写出的，没写就为空。入账请用记一笔或导入文件。
- 你发送的问题、今日数据、工具结果和图片会发给你配置的模型服务商。回答只供参考，不构成投资建议。

## 设置

地址 `/settings/<分区>`：

| 分区 | 内容 |
|---|---|
| 账户与费率 | 每个账户的费率，记一笔时按它预填费用估算；实际费用以成交单为准 |
| 模型 | 对话助手用的模型，和研究工作台的模型连接；研究模式（`make lab`）没有启动对话助手，对话模型不能在这里保存，页面写明原因 |
| 数据与行情 | 行情源状态、日线缓存，以及交易日历覆盖哪些年份 |
| 自动化与通知 | 提醒监控、每日例行任务（状态、下次运行、**立即运行**）、通知渠道；开关和时间在后端启动时从环境变量读取，不在页面里保存 |
| 交易偏好 | 交易画像、情绪触发点、交易教训，以及助手提出待确认的修改；可清空助手记忆。删除教训时只删页面上显示的那一条：另一个标签页已经改动过列表时会拒绝，并重新读取列表。教训没有单独的页面，就在这里 |
| 备份与导出 | 下载账本和桌面数据的备份，导出流水 |
| 关于与帮助 | 版本、运行模式、外观（跟随系统 / 浅色 / 深色，默认跟随系统，只保存在这个浏览器）、重新运行设置向导、快捷键、文档链接 |

快捷键：`N` 记一笔，`Ctrl K` / `⌘K` 或 `/` 搜索代码或名称，`?` 快捷键列表，`Esc` 关闭对话框、抽屉或助手。

网页每分钟会重新读取后端的运行模式，后端中断后恢复时也会读：后端换成演示模式或正常模式重启后，顶部提示和写入按钮跟着变化，不用刷新页面。

## 备份与恢复

设置 › 备份与导出 有两个下载按钮：**下载账本备份** 得到 `ledger-backup.sqlite3`，**下载桌面数据备份** 得到
`desk-backup.sqlite3`。它们是后端运行中生成的一致副本，对应数据目录里的两个文件：

- **账本**（`ledger.sqlite3`）：全部已确认的流水（期初、买卖、分红、入金出金、换汇、拆股和冲销）、还没确认的账本方案（记一笔、导入、助手提出的）、研究笔记；
- **桌面数据**（`desk.sqlite3`）：价格提醒规则和触发记录、交易计划及其与成交的关联、自选列表、助手提出的方案（包括你放弃过的教训和画像修改）、
  盘前盘后简报和每日例行任务的运行记录、导入记录、列对应和代码别名、各账户的费率、站内通知和设置向导的完成状态。

**不在这两个备份里**：助手的记忆（后端目录下的 `data/memory.json`）、模型设置和 API 密钥（`config.json`、`.env`）、
研究工作台的实验、回测历史和日线缓存、旧版持仓文件和收盘快照（数据目录里的 JSON 和 CSV 文件）。需要时请另外备份。
**导出流水** 生成 JSON，便于查看，不能用来恢复。

两份备份分两次下载，各自是下载那一刻的内容；两次下载之间记了交易的话，两份会对不上。备份时请先不要记账，连续下载两份。

恢复（页面上的说法是：先停止后端，再用备份替换数据目录里的同名文件，然后启动）：

1. 关闭所有已打开的网页，停止后端（`make stop`；Docker 用 `docker compose stop backend`）和所有会写数据目录的定时任务；
2. 把数据目录（`PORTFOLIO_DIR`，默认 `engine/portfolio`；Docker 中是挂载进容器的同一个 `engine/portfolio`）里现有的
   `ledger.sqlite3`、`desk.sqlite3` 和同名的 `-wal`、`-shm` 文件移到别处；
3. 可选：用 SQLite 的 `PRAGMA integrity_check` 检查备份，结果必须是 `ok`；
4. 把 `ledger-backup.sqlite3` 改名为 `ledger.sqlite3`、`desk-backup.sqlite3` 改名为 `desk.sqlite3`，放进数据目录；
5. 启动后端，再打开网页，核对账户余额、流水条数、提醒、计划和研究笔记。

只恢复其中一个文件也可以；但两个文件来自不同时间时，导入记录、计划与成交的关联可能对不上，最好成对恢复。

为什么要先关网页：页面开着时恢复，新通知可能沿用恢复前的编号，点开旧通知会把新的提醒一起标为已读。
另外，备份之后已经确认过的提议，恢复后再次确认会显示「已应用」但不会再生效，这类改动请到设置里直接修改。

## 从 v3.2 升级

1. 先备份：3.2 在账本页点 **备份**（3.2 还没有桌面数据文件）；或停止后端，把数据目录（默认 `engine/portfolio`）里的
   `ledger.sqlite3` 和 `desk.sqlite3`（如有）复制到安全的地方。还在用旧版持仓文件的话，备份整个数据目录。
   恢复方法见[备份与恢复](#备份与恢复)。
2. 更新代码后运行 `make setup`（Python 和 Node 依赖有变化）。
3. 数据库结构自动升级：`desk.sqlite3` 第一次写入时创建，已有的在后端启动时升级（演示模式除外）；`ledger.sqlite3` 第一次写入时增加一张表；
   回测历史 `backtest_history.db` 第一次写入时补列（只读打开时按原样读取旧版本的文件，只读的副本也能读），已有的日线缓存
   `backtesting.db` 打开时补表。只读（打开页面、助手读取数据）不会创建文件，也不会改动账本和桌面数据。
4. 启动后打开 `/setup`。还没有账本时，选 **迁移旧版持仓** 或 **导入券商文件** 建立期初；已有账本时在这里检查费率、行情、提醒和例行任务。
5. 旧的「持仓」页、`POST /api/settings/cash` 和 `/api/portfolio` 的持仓接口在账本启用后返回 409，下个版本删除。旧链接会跳转：
   `/portfolio` → `/ledger`，`/memory` → `/settings/preferences`，`/help` → `/settings/about`，`/dashboard` → `/`。
6. RSI、ATR、ADX、MFI 改为标准定义，用到它们的旧回测结果会不同。v3.2 保存的回测没有运行清单，打开时标为「旧版本记录」，
   缺少的部分显示不可用，可以导出，但不能重跑（「这条记录是旧版本保存的，缺少复现所需的设置（运行清单），无法重跑」）。
7. 互相重复的提醒规则（如 `HKG:700` 和 `HKG:00700` 同一阈值）会在升级后第一次写入时合并：最早的一条保留，其余停用并写明原因，同时发一条通知。
   这样停用的重复规则不会妨碍你停用或修改保留下来的那条，它自己的备注也可以改；但保留的那条还在时，不能再启用它。
8. 升级前还没确认的导入预览（包括 3.2 版 CSV 导入生成的）确认时会被拒绝一次并撤回，请重新导入同一个文件。
   升级前生成的 B 股方案确认时会被拒绝，直接放弃即可。
9. 原来用 `portfolio_scheduler.py` 或 cron 生成每日快照的，可以停掉；继续保留也不会重复生成同一天的快照。

## 页面上的提示是什么意思

| 提示 | 含义 | 怎么办 |
|---|---|---|
| 不可用 | 取不到可用的价格、汇率或数据，相关数字和包含它的合计都不显示（不会当成 0） | 鼠标悬停看原因；稍后点 **刷新**，或检查网络和代理 |
| 估算 | 数字是用未经核实的价格或汇率算的（如已过期的价格、昨收价、交易所时间未知、汇率过期、没有节假日表的年份的收盘价，或还没最终确定的美股收盘价） | 数字可以参考，但不是核实过的；行情恢复后会自动变回正常 |
| 已过期 hh:mm | 交易时段内价格超过 20 分钟没有更新，或收盘后拿到的不是收盘价 | 通常是数据源延迟或中断，等待或刷新 |
| 延迟 | 价格比交易所时间晚 1–20 分钟（如雅虎的港股行情约晚 15 分钟） | 仍按核实价格使用 |
| 收盘价 hh:mm | 最近一个交易日的收盘价 | 无需处理；在没有节假日表的年份标为估算；美股收盘后 30 分钟内悬停写「收盘价尚未最终确定」，也标为估算，之后自动变成核实的收盘价 |
| ≈ 加数字 | 超过 8 位小数的数字只显示 8 位 | 鼠标悬停看完整值；入账和计算用的都是完整值 |
| 等待中 | 收盘快照在等收盘价确定（如「等待港股收盘价确定，16:10 后记入」「……最晚 16:28 记入」） | 无需处理，到时自动生成；不是失败；想马上再查一次可以手动运行 |
| 含估算 | 这一天的快照用到了估算的价格、汇率或旧版持仓文件 | 复盘前先核对；这一天不会自动重做 |
| 旧版本记录 | v3.2.1 及更早保存的回测结果，只有当时保存的部分 | 只能查看和导出，不能重跑 |
| 期末估值（未卖出） | 回测结束时还没卖出的持仓，按最后收盘价估值 | 见回测结果的「期末仍持有」；不算完整交易 |
| 未核对 | 导入对账时，还有会影响这笔余额的行没算进去 | 先处理需处理的行或勾选相关的行，再看对账 |
| 昨收价 | 今天还没有成交（开盘前或停牌），按昨收估值 | 无需处理；价格提醒在这种情况下不检查 |
| 时间未知 | 数据源给了价格，但没有可用的交易所时间 | 按估算显示，提醒不使用 |
| 交易日历未核实（按工作日推算） | 这一年还没有收录交易所节假日表，只按工作日判断 | 节假日可能被当成交易日；等新版本收录 |
| 暂停检查 | 提醒监控暂时不检查这条规则（价格过期、不可用、未成交，或仓位只是估算），后面写着原因和开始时间 | 行情恢复后会自动继续 |
| 休市，不检查 | 规则所在市场不在连续竞价时段 | 无需处理 |
| 预览已过期 | 账本在这次预览之后有了变化，或手动预览超过 2 小时 | 返回修改后重新预览 |
| 需处理 | 导入的这一行缺少或无法确定入账需要的信息 | 点开这一行按提示改正，或设为跳过 |
| 可能重复 | 账本里已有相似的记录 | 确认不是同一笔再勾选 |
| 预设未经你的券商文件验证 | 导入格式按公开列名写成，没有用你的券商文件验证 | 在「核对列」里核对每一列 |
| 今日快照 不会自动生成 | 后台调度器没有运行（例如演示模式） | 正常模式下启动后端 |
| 连接中断 / 数据未更新 | 网页一段时间没收到后端的数据，显示的是旧数据 | 检查后端是否在运行，点 **重试** |
| 演示模式 · 数据为虚构，只读 | 正在使用演示数据 | 用 `make start` 启动自己的数据 |

## 常见问题

**打开网页显示「连接中断」或一片空白。** 后端没有运行或启动失败。看运行 `make start` 的终端输出；`Backend dependencies are missing. Run make setup first.`
表示还没装依赖；端口被占用时换 `BACKEND_PORT` / `FRONTEND_PORT`。`Backend did not become ready within 30 seconds (BACKEND_START_TIMEOUT).`
表示后端 30 秒内没有响应，机器较慢或负载高时常见：用 `BACKEND_START_TIMEOUT=120 make start` 多等一会儿（1 到 3600 秒）。
Docker 下 `docker compose up` 报后端 `unhealthy` 时，在仓库根目录的 `.env` 写 `BACKEND_START_TIMEOUT=120`，
健康检查在这段时间内不把失败计数。

**接口返回 `400 Invalid host header`。** 用了 `localhost` 以外的名字打开。把它加到 `TRACKER_ALLOWED_HOSTS` 并重启后端，先读 [安全说明](SECURITY.md)。

**今日页显示「还没有已确认的持仓」。** 账本里还没有期初余额。打开 `/setup`，或在 账本 › 导入 导入持仓文件，或用记一笔的「期初余额」。

**行情全部「不可用」。** 东方财富、腾讯和雅虎都没取到。检查网络；需要代理时设置 `TRACKER_EASTMONEY_PROXY=1`、`TRACKER_TENCENT_PROXY=1`（使用环境里的代理）或 `TRACKER_YAHOO_PROXY`，重启后端。
设置 › 数据与行情 显示各行情源的状态。

**提醒没有触发。** 先看提醒页的「监控」一行：后端是否在运行、是否「待命」或「已关闭」；再看规则状态是否为「暂停检查」或「休市，不检查」。
提醒只在连续竞价时段、使用可信价格时检查。

**今日快照「不可用」。** 看悬停说明：Docker 后端镜像不含快照引擎（在宿主机运行手动命令）；数据目录没有 `config.json`（运行 `make setup`）；
或这一天没有生效的持仓。

**今日快照「失败」。** 多半是某个持仓取不到价格（不会按 0 计算）。行情恢复后在 设置 › 自动化与通知 点 **立即运行**。

**记一笔提示 B 股不支持。** 账本按人民币记录沪深标的，B 股以美元或港币交易，暂不支持。

**确认入账时提示「这份入账预览已作废」。** 导入在生成预览后被修改、删除或过期，或账本有了变化。回到导入页重新 **生成入账预览**。

**接口返回「系统正忙，暂时无法处理。请稍后重试。」** 另一个写入（如提醒监控、例行任务）正持有数据库锁，稍后重试即可。

**启动日志里有一行 `SQLite 3.51.1 can deadlock when threads open and close one database file; …`（或 3.51.0）。** SQLite 3.51.0 和 3.51.1
（conda 的 Python 3.11 在 2026 年初附带 3.51.1）有一个在 3.51.2 修复的死锁：同一进程里多个线程同时打开和关闭同一个数据库文件时，
两边都不返回。在这两个版本上，程序会自动把数据库的「打开／关闭」串行化（`dashboard/core/sqlite_guard.py`），并在后端启动日志里写这一行；
其他版本不受影响，也不会有这行。建议升级 SQLite（如 `conda update sqlite`）；当前版本可用
`python3 -c 'import sqlite3; print(sqlite3.sqlite_version)'` 查看。

**旧版接口返回「账本已启用：现金请在交易账本中记录（入金、出金、换汇），这里的旧版现金设置已停用。」** 账本启用后旧的现金和持仓接口停用，请用记一笔。

**演示模式下按钮不可用。** 演示数据只读（接口返回 `Demo mode is read-only`）。用 `make start` 使用自己的数据。

**导入时提示「文件超过 5 MB。请缩短导出的日期范围后再试。」** 分几段日期导出再分别导入；重复的行会显示「已导入」。

**pip 安装失败、找不到包。** 可能是 pip 指向了内部镜像，可指定 PyPI：`python3 -m pip install -r dashboard/requirements.txt -i https://pypi.org/simple/`。
